# Plugin evals in CI

Decision record for [#436](https://github.com/dfadler/agent-config/issues/436). Full research and the per-question rationale are in the
[recommendation comment](https://github.com/dfadler/agent-config/issues/436#issuecomment-5940264329);
CLI facts are from the [plugin-evals docs](https://code.claude.com/docs/en/plugin-evals).

Workflow: `.github/workflows/plugin-evals.yml` (#582); result checker: #583. Recommendation:

- **Trigger:** `workflow_dispatch` only. The weekly run is a local scheduled task (see Alerting). Never `schedule` or `pull_request` (public repo, `--trust-plugin`, paid key).
- **Scope:** plugins that have `evals/` (today `fetch-execute-guide`), one matrix entry each, after #442 removes vacuous cases.
- **Gate:** hard-fail on the run-evals wrapper's exit code. The wrapper fixes `--threshold` at 1 (every grader must pass), so the earlier 0.8 start is dropped; #584 calibrates Δ, not a pass threshold. Δ is a gate with `--delta-floor 0` (#585): a case with `delta < 0` (the plugin hurts) is a regression, and a missing `delta` still means "no signal". Owner decision after the #584 pilot, where Δ run-to-run noise was about 0.0 to 0.2 on stable plugins, so a floor of 0 trips only when the plugin scores below no plugin. Risk: a stays-quiet case where the no-plugin arm scores 1.00 can trip on noise if the with-plugin arm dips.
- **Runner:** the `run-evals.ts` wrapper at the `standard` tier (every case, 3 runs, with and without the plugin, `--max-cost-usd 5`, `--no-publish`, models pinned in the wrapper). It applies each case's `grants.yaml` grants, which a raw `claude plugin eval` call would not, so cases that need Bash can pass.
- **Invalid runs:** exit 2, `partial: true`, `skippedPaidGraders`, or any `arms.with[].error` fail the job as inconclusive, not as a regression. So does an implausible result (#734, #735): empty `cases`, a case with no with-arm runs, a wrong `schemaVersion`, dropped malformed entries, a run scoring 0 with no grader detail, or every run scoring 0.
- **Auth:** `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`, a one-year token for a Pro, Max, Team or Enterprise plan) in a protected `plugin-evals` environment, per the [authentication docs](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token). Replaces the earlier spend-capped `ANTHROPIC_API_KEY` plan. Consequences:
  - Runs count against the plan's usage limits, shared with interactive use. `--max-cost-usd` is a list-price ceiling, not a spend cap.
  - A run that hits the usage limit scores 0 and is not marked `partial` ([troubleshooting](https://code.claude.com/docs/en/plugin-evals)); the checker treats an `arms.with[].error` or `arms.without[].error` as inconclusive (the without-arm check lands in #599), so it shows as exit 7, not a regression. A silent zero (score 0, no grader detail, no `error`) and an all-zero run are also exit 7 (#735).
  - The token expires after a year: rotate the secret. Anyone who can read it can use the plan, so keep it in the protected environment with required reviewers and never expose it to `pull_request` runs.
  - The plugin-evals page documents `ANTHROPIC_API_KEY` for CI and says eval uses "the same authentication" as normal sessions; it does not name `CLAUDE_CODE_OAUTH_TOKEN`. Confirm with one `workflow_dispatch` run before relying on the schedule.
- **Plugins without `evals/`:** the `plan` job warns and lists any plugin with `skills/`, `agents/` or a root `SKILL.md` but no `evals/` (#648), so a gap shows in the step summary instead of the plugin silently dropping out of the matrix. Warn-only.
- **Plugin-arm-only agent cases** (`shell-script-reviewer`, `vite`'s reviewer, `adversarial-reviewer`, `docs-staleness-checker`, `playwright`'s agent, `vitest`'s investigator): the no-plugin arm cannot dispatch a plugin agent, so these cases run `--ablation none` and have no Δ. They are gated by the absolute pass bar (wrapper exit, every grader passes) and the checker's validity checks, not by Δ; the checker skips cases with no `delta` under the Δ floor (#585). Decision (#648): **make the pass bar itself strict (c) first.** Each case carries free deterministic graders on the report contents: dispatch (`tool_used` Agent), setup files (`file_exists`), report-only (`tool_used` Write min/max plus a `regex` on the reviewed file still containing the planted defect), and one `regex` on `last_message` per planted defect, anchored on a token from the fixture. **Escape hatch (b), a with-arm-only threshold below 1, only for a case that stays noisy after that**, meaning a grader that fails on a correct report because the wording varies and cannot be narrowed to a stable token. It is not implemented: the wrapper passes one `--threshold` per tier (`tiers.ts`) to a single `claude plugin eval` call, so a per-case value needs the wrapper to split cases into separate invocations (or the CLI to accept a per-case threshold). Until then, narrow or split the noisy grader (lowering its `weight` does not help: at threshold 1 every positive-weight grader must still pass), and record the noisy case in the issue before asking for the wrapper change.
- **Weekly run and alerting (#738):** not a GitHub cron. A local Claude scheduled task (`plugin-evals-weekly`, Mondays 09:00 local) runs the wrapper per plugin from a detached `origin/main` worktree, checks each `aggregate-result.json` with `check-plugin-eval.ts`, and saves results under `~/.claude/plugin-eval-results/<date>/` (a local baseline). It runs only while the Claude app is open, and runs on next launch if missed. Its session summary is the alert; nothing is filed on GitHub.
- **Ungated cases (#738):** the `Check results` step lists every case with no `delta` in the step summary, so a plugin-arm-only case shows as ungated by delta instead of being skipped silently.
- **Open decisions (#738):** (1) a committed baseline: `evals/results/` is gitignored and artifacts expire after 30 days; committing one `aggregate-result.json` (or a compact summary) per release needs a write path from CI (a bot PR or a protected push), which is an owner call. (2) a judge model different from the agent: `DEFAULT_MODEL` and `DEFAULT_JUDGE_MODEL` in `tiers.ts` are both `claude-sonnet-5-5`; changing the judge shifts every score, so recalibrate Δ (#584) first.
- **Concurrency:** `group: plugin-evals`, `cancel-in-progress: false`.

Open owner questions (weekly spend, a capped key) are listed in the comment; the Δ floor is settled at 0.
